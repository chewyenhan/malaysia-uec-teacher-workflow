# AI Agent 直接生成 PPTX：必执行流程

选用 editable 时必须读取本文件。工具可以按环境选择，输入、顺序、成品与验收不能自行省略。使用本地程序或当前 Agent 的原生演示文稿工具生成真实 PPTX，不把提示词、HTML、PDF 或安装说明当作 PPTX。

## 1. 开始条件

先完成教材盘点、考纲／课程依据核证、详细教案、slides-outline.md 和 teacher-notes.md。确认课时、课堂投影用途、页数、语言、视觉风格和是否要求可编辑。已有选择沿用；缺项同轮问齐。付费服务先取得相应授权。

## 2. 建逐页制作规格

保存 slide-specs.json，至少记录 canvas（默认16:9）、theme（字体、字号、颜色）、pages。每页必须记录 id、title、layout、content、visuals、source_refs 和 notes_ref；页面 id 与大纲 P01 等一致。教材来源不可用时标记待核，不能编造引用。

页面内容由已有大纲派生，不能另写一套主题；详细讲解放讲稿，每页投影文字精简。视觉描述须写具体构图、图表／地图内容、标签及活动呈现方式，不只写“美观”或“Q版”。保留目标、学生活动、提问和课末检查，不因排版删掉教学环节。

## 3. 检查工具并确定实现

确认当前工具能够输出真实 PPTX 和渲染预览。原生演示文稿工具可用则优先；否则使用已安装且可执行的 python-pptx 或 PptxGenJS 等。只使用实际验证过的接口，不猜工具命令。不为了课件搭建无关服务。

正文、标题和标签使用真实文本框；图表／公式按编辑要求制作。图片可作背景或辅助素材，不能用整页图片冒充可编辑课件。需要 AI 生图时采用无文字底图＋真实字体文字层；不把中文交给图片模型绘制。没有可用生图服务时说明视觉替代方案，不静默改变教师指定风格。

## 4. 先制作代表样张

先做一页代表性内容页，包含标题、正文和主要视觉元素，渲染并检查中文字体、阅读字号、颜色对比、边界和素材正确性。AI 生图样张须展示给教师确认（沿用已有授权）；普通排版路线按本次授权确认或自检并保存证据。样张不合格先修正，不批量复制错误。

## 5. 按规格批量生成

逐页严格按 slide-specs.json 顺序组装 teaching-slides.pptx。保留生成脚本或工具项目以便修改。嵌入字体支持的中文文本，保持相同主题；有图片必须实际嵌入，不留本机路径占位或失效远程链接。讲稿写入演讲者备注（工具支持时），独立 teacher-notes.md 始终交付。

## 6. 三份逐页对账

比较实际 PPTX、大纲、讲稿的页数、页序、标题和内容。修订页面时同步规格、大纲及讲稿，教案中的 PPT 页码也同步。不能只因页数相同就判定对应。

## 7. 实际验收与修正

检查 PPTX ZIP／XML 结构和实际幻灯片数；逐页渲染并打开预览，核对中文、事实、公式、图表、错位、截断、遮挡、缺图和投影可读性。声称可编辑前核对实际文本框并做一次编辑保存验证。错误页原地修正，重新渲染对应页面；没有渲染工具则记录画面待核，不能说验收全部通过。

运行 check_lesson_bundle.py 作结构辅助检查，内容与视觉检查另记 qa-report.md，报告实际通过计数、未核项目和证据位置。

## 8. 交付与失败恢复

交付详细教案、PPT 大纲、逐页教师讲稿和 teaching-slides.pptx 四项链接，以及实际可编辑程度和验收结果。保留 task-state.json 的所选路线、工具、规格路径、输出与下一步。失败时复用已完成文件，只修复缺失环节；未经教师选择不能改用 NotebookLM 或 outline-only。

生成后和后续修改时必须执行 [PPT同步关卡](ppt-synchronization.md)，保存逐页映射及四份成品摘要；最终验收不得跳过。

选择风格和制作前必须读取 [完整PPT风格库](slide-style-library.md)；将所选风格落实到每页构图、配色和文字布局，并以样张检查全片一致性。
